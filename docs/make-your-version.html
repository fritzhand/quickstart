Step 4 · Make it yours

Make your own version

Turn the Tampa starter into a history of your own city, one prompt at a time. The example is St. Petersburg, Florida, in a repo called history-of-st-pete.

Time: About 1 hour

Do the steps in order. Read what the agent says back after each one before you send the next.

  1. Get your copy

    Say this
    Fork fritzhand/history-of-tampa into my account and name the fork your-repo.

    If the agent can't fork it

    Open https://github.com/fritzhand/history-of-tampa (opens in a new tab) and click Fork in the top-right corner. Type your-repo as the repository name, in lowercase, and click Create fork.

    Want your commits to count on your GitHub profile? Make a fresh copy instead, with a session that holds both repos. Clone, fork or copy shows how.

  2. Start a session in your repo and set the rules

    App path

    Start a new session. Pick your-username/your-repo in the repository selector, and add fritzhand/history-of-tampa as a reference, as shown in Many repos, one to work in. Fork not in the list? Add it to the Claude GitHub App, as shown in Claude Code in the app.

    VS Code path

    Open your projects folder in VS Code, then say:

    Say this
    Clone https://github.com/your-username/your-repo into this folder and open it.

    Then send the rules as your first message:

    Say this
    Work only in your-username/your-repo. Treat the other repos as read-only reference. Commit as Your Name <your-noreply-email>. Push finished work straight to main. Only use facts you can cite with a link, and mark anything you can't verify as TBD. Write these rules into a CLAUDE.md file at the root of my repo so every session follows them. Then commit and push to main.

    Using Codex? Say AGENTS.md instead of CLAUDE.md.

  3. Clean out the original owner's things

    The starter still carries its author's analytics tag, photo, name and links. Left in, the tag would send your visitors' data to the original author.

    Say this
    In index.html, remove the Google Analytics tag. Delete assets/jeremy.jpg and the author photo and name blocks in the byline, the About section and the credit footer. Delete the files I won't use: ybor.html, js/ybor-data.js, the assets/linkedin and assets/linkedin-ybor folders, and the LinkedIn tools in tools/. Remove any links to the deleted pages. Replace every https://fritzhand.github.io/history-of-tampa/ address with https://your-username.github.io/your-repo/ and point the Repository links to my repo. Then list what you removed.

  4. Research first, then build

    Get the facts before the agent writes a word of your site. That keeps invented numbers out.

    Say this
    Research the history of St. Petersburg, Florida, for this site. Use real sources, such as city, county and state archives, universities, the Census Bureau and newspapers, and give a working link for every fact, date and number. Wikipedia can point you to sources but isn't one. List images only if they're public domain or openly licensed, with a credit line. Write everything to research/notes.md and mark anything you couldn't verify as TBD. Never invent a number, date or link. Don't change the site yet.

    Read research/notes.md yourself. You know your city: delete anything that looks wrong.

    If the agent can't open websites

    On the app path, the cloud machine may block most websites. Paste the same research prompt into a regular Claude chat with web search on. Then bring the answer back to your session:

    Say this
    Put these research results in research/notes.md exactly as written, then commit and push to main: paste the results

  5. Make the change

    This is the biggest edit, so ask for a plan first: add "Plan this first. Don't change anything until I say go."

    Say this
    Using only the facts in research/notes.md, rewrite js/data.js and the text in index.html for St. Petersburg, Florida. Keep the data file's format and variable name so the site still works. Remove any section I have no data for instead of leaving it empty. Keep a line in the footer that says "Forked from fritzhand/history-of-tampa" with a link to it. Then show me what you changed in plain English.

  6. Check

    Say this
    Search the whole repo, ignoring capitals, for leftover words from the original: Tampa, Ybor and fritzhand. Keep the "Forked from" credit, delete planning files that are only about Tampa, and fix everything else, including README.md. Run any checks this repo has, such as tools/validate-data.mjs, and fix what they report. Then summarize what changed in plain English.

  7. Commit and push to main, then publish

    Say this
    Commit and push to main.

    Now switch on your site: Turn on GitHub Pages, from main and / (root).

Keep a PROGRESS.md

Each session starts fresh. End every session with:

Say this
Update PROGRESS.md with what's done and what's next, then commit and push to main.

Start the next one with "Read PROGRESS.md and continue from what's next."

Check it worked

Open https://github.com/your-username/your-repo. The README describes your city, CLAUDE.md holds your rules, and the newest commit on main shows your name, not Claude's.

Starting from startup-india-guide instead?

Use fritzhand/startup-india-guide in steps 1 and 2. Swap step 3 for this prompt:

Say this
Work only in your-username/your-repo. Treat the other repos as read-only reference. In site.config.json, set siteName to "My Guide", siteBase to https://your-username.github.io/your-repo/, pathPrefix to /your-repo/ and repo to https://github.com/your-username/your-repo, and delete analyticsId. Delete the .github/workflows folder and scripts/fetch-india-news.py; they run a daily news bot and a deploy I don't need. Replace the author footer in build.mjs with my name, Your Name, and delete site/jeremy.png. Run node build.mjs until it finishes without errors, then commit and push to main.

Steps 4 to 6 work the same way, but the content lives in the data/ folder, and in step 6 you search for India and fritzhand. Publish from main and /docs. Much of build.mjs is written for India, so rewriting it for your topic takes several sessions. Ask for a plan first.

If it goes wrong

The site looks broken after a change

Describe what you see and let the agent compare it with the original:

Say this
The page now describe what looks wrong. Compare my repo with fritzhand/history-of-tampa, find what broke and fix it.

Or go back one step: "Revert the last commit and push to main."

A number or source looks made up
Say this
Check every figure in js/data.js against research/notes.md. Remove anything that has no working source link, or mark it TBD. List what you changed.
What the agent runs for you 
# Fork and clone (GitHub CLI)
gh repo fork fritzhand/history-of-tampa --clone --fork-name your-repo

# Find leftover words from the original
grep -rniE "tampa|ybor|fritzhand" --exclude-dir=.git .

# The starter's own data check (needs Node)
node tools/validate-data.mjs

# Save and publish
git add .
git commit -m "Rewrite the site for St. Petersburg"
git push origin main
