Reference

Prompt cheat sheet

The prompts you'll use most, in one place and grouped by what you're doing. Copy one, fill in the highlighted parts, and paste or dictate it to the agent.

Time: 2 min

Tap Add your details under any prompt once, and the highlighted parts fill in with your username, repo, name and email. Each prompt links to the page that explains it.

Set the rules

Name the one repo to change
Work only in your-username/your-repo. Treat the other repos as read-only reference.

Say it first in any session that has more than one repo. Explained in Many repos, one to work in.

Commit as yourself (add to any prompt)
Commit as Your Name <your-noreply-email>.
Commit as yourself, this session (app path)
For this repo, set git user.name to "Your Name" and user.email to "your-noreply-email", and commit as me from now on.
Commit as yourself, this computer (VS Code path)
Set my global git name to "Your Name" and email to "your-noreply-email".

Explained in Commit as yourself.

All the rules at once
Work only in your-username/your-repo. Treat the other repos as read-only reference. Commit as Your Name <your-noreply-email>. Push finished work straight to main. Only use facts you can cite with a link, and mark anything you can't verify as TBD. Write these rules into a CLAUDE.md file at the root of my repo so every session follows them. Then commit and push to main.

Explained in Make your own version.

Starter CLAUDE.md

A CLAUDE.md file at the root of your repo holds standing rules. Claude reads it at the start of every session, so you don't have to repeat yourself. Send this once in each repo:

Create a starter CLAUDE.md
Create a CLAUDE.md file at the root of this repo (or add to it if it exists) with these rules, then commit and push to main:
- Work only in your-username/your-repo. Treat the other repos as read-only reference.
- Always commit as Your Name <your-noreply-email>.
- When a piece of work is finished, commit and push to main.
- Never invent facts. Give a working link for every fact, date and number, and mark anything you can't verify as TBD.
- Keep PROGRESS.md updated with what's done and what's next.
- Ask me before deleting any file.

Using Codex? Say AGENTS.md instead of CLAUDE.md. Explained in Commit as yourself and The big picture.

Change your site

Research before writing
Research the history of St. Petersburg, Florida, for this site. Use real sources, such as city, county and state archives, universities, the Census Bureau and newspapers, and give a working link for every fact, date and number. Wikipedia can point you to sources but isn't one. List images only if they're public domain or openly licensed, with a credit line. Write everything to research/notes.md and mark anything you couldn't verify as TBD. Never invent a number, date or link. Don't change the site yet.

Explained in Make your own version.

Make a change: what, where, done
In your-username/your-repo, change the site title to "A History of St. Petersburg" and rewrite the opening section about St. Petersburg, Florida. Cite a link for every fact you add. Done means the opening section no longer mentions Tampa.
Keep facts honest (add to any prompt)
Only use facts you can cite with a link. Mark anything you can't verify as TBD.

Explained in How to talk to the agent.

Add a section
Add a section about the topic after the section it should follow. Research it first, give a working link for every fact, and mark anything you can't verify as TBD.
Add an image, with credit
Add a photo of the subject to the section. Use only an image that's public domain or openly licensed, show its credit line under it, and tell me where you found it.
Swap the colors
Change the site's colors to deep blue and sand. Keep the text easy to read in both light and dark mode.
Fix broken links
Check every link on the site, fix or remove the broken ones, and list what you changed.

Explained in Update & share.

Publish

Turn on GitHub Pages (VS Code path)
Turn on GitHub Pages for your-username/your-repo from the main branch, root folder (or /docs if the site lives in docs/), using the GitHub CLI, then tell me the URL.

On the app path you switch Pages on yourself, once. Explained in Turn on GitHub Pages.

Check before you push (app path)
Before you push, check my site for missing files, broken image paths and JavaScript errors, and tell me what you find.
Preview on your computer (VS Code path)
Start a local preview of my site and give me the link.
Is my change live?
Is my last commit pushed to main on GitHub? If not, push it to main.
Set up the link preview (optional)
Set up the link preview for my site: its title, a one-line description and a 1200×630 share image showing the site's title, all pointing to https://your-username.github.io/your-repo/. If you can't make an image, remove the image tags instead. Then commit and push to main.

Explained in Update & share.

When stuck

Paste the error
Here's the error: paste the exact error. Explain what went wrong in plain English and fix it.

Explained in How to talk to the agent.

Explain what happened
Explain what you just did and why, in plain English. Don't change anything.
Ask for options
Give me two or three ways to fix this, with the pros and cons of each in plain English. Don't change anything until I choose.
Start over with a clear goal
Here's what I want: what done looks like. Here's the exact error: paste the exact error. Tell me what you think is wrong and your plan. Don't change anything until I say go.

Send that last one in a new session. Explained in Troubleshooting.

Check which repo it changed
Which repo are you working in, and which files did you change?

Explained in Many repos, one to work in.

A rejected push, a merge conflict, a 404 page or a site with no styling each has its own fix in Troubleshooting.
