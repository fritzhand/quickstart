A branch is a parallel line of work in the same repo. You can make changes on a branch without touching the main line. main is the line GitHub Pages publishes from, so your site updates only when main changes.

Make sure it's called main

Repos you create on GitHub already use main. Git on your own computer may still call a brand-new repo's first branch master, so on the VS Code path say this when the agent starts a new repo:

Start a new git repository here on a branch named main.

Have an older repo that uses master?

Rename the master branch to main, push it, and make main the default branch on GitHub.

The app path: Claude's own branch

In the Claude app, Claude works on its own branch, named claude/…, and pushes that branch, not main. Your site doesn't change until the work is merged into main.

Two ways to get work onto main

Straight to main

The simplest way for a project only you work on. Say it with the task, or at the start of the session:

Commit and push to main.

Through a pull request

Let Claude push its claude/… branch, then say:

Open a pull request into main and merge it.

Or tap Create PR at the top of the diff view. Then open the pull request on GitHub, click Merge pull request, then Confirm merge.

On the VS Code path the agent usually works on main already, so "Commit and push to main." is all you need.

Open https://github.com/your-username/your-repo/commits/main. Your change is the newest commit on main.

If it goes wrong

The agent says it can't push to main

Use the pull request way instead:

Push your branch, then open a pull request into main and merge it.
The agent pushed, but my site didn't change

The work is probably still on a claude/… branch. Ask:

Which branch is my work on? Get it onto main and push main.

After main changes, give GitHub Pages up to 10 minutes.

What the agent runs for you 
# A new repo that starts on main
git init -b main
git config --global init.defaultBranch main   # every new repo from now on

# Rename an old master branch
git branch -M main
git push -u origin main
gh repo edit --default-branch main

# Pull request, then merge (GitHub CLI)
gh pr create --base main --fill
gh pr merge --merge

On the app path, Claude may use its built-in GitHub tools for the pull request instead.
