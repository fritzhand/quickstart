The agent

Agent
An AI program that works on your files for you: it reads them, edits them and runs commands, then tells you what it did. In this guide the agent is Claude Code or Codex. See The big picture.
Claude Code
Anthropic's coding agent. You can use it in the Claude app, in a browser, on your phone or on your desktop, or as an extension inside VS Code. It needs a paid Claude plan. See App or VS Code?
Codex
OpenAI's coding agent. This guide uses its VS Code extension, which needs ChatGPT Plus or higher. See VS Code + your agent.
Prompt
What you type or say to the agent. A good one says what you want, where, and what done looks like. See How to talk to the agent.
Session
One conversation with the agent. A new session doesn't carry over your earlier conversations, so standing rules go in CLAUDE.md. See The big picture.
Dictation
Speaking instead of typing. Your phone, Mac or Windows computer turns what you say into text in the message box. See How to talk to the agent.
Placeholder
A highlighted part of a prompt, like your-username, that stands for your own details. Save your details in this guide and it fills them in for you. See Create your GitHub account.
CLAUDE.md
A plain text file at the root, or top folder, of your repo that holds standing rules, such as who to commit as. Claude reads it at the start of every session. Codex reads a file called AGENTS.md instead. See Prompt cheat sheet.
Claude GitHub App
A GitHub add-on that gives Claude in the app access to the repos you choose. Claude needs it to work in a private repo. See Claude Code in the app.

Git and GitHub

GitHub
A website that stores your repos and their history, and can publish them as websites. A free account is all you need. See Create your GitHub account.
Git
The tool that records every saved version of your files and sends them to GitHub. The agent runs it for you. See Git, Node & GitHub CLI.
Repository (repo)
Your project's folder on GitHub, plus the history of every saved change. Your site lives in one repo. See Repos: public or private.
Public and private
Who can see a repo. Anyone can see a public repo, including its history. Only you and people you invite can see a private one. On a free account, GitHub Pages works only from public repos.
README
The file GitHub shows on a repo's front page, usually README.md. It says what the repo is.
Commit
A save point for the whole project, with a short note that says what changed. You can go back to any commit. See Commit & push.
Author
The name and email recorded on each commit. GitHub credits the commit to the account that owns the email, so use your noreply address. See Commit as yourself.
Noreply email
A private address GitHub gives you, ending in @users.noreply.github.com. Use it as your commit email: it credits you without putting your real email in public. See Create your GitHub account.
Push
Sends your commits up to GitHub. Until you push, they exist only in the working copy. A force-push overwrites what's on GitHub, so avoid it. See Commit & push.
Pull
Brings changes down from GitHub into your working copy, such as edits you made on another device. See Commit & push.
Clone
A working copy of a repo, on your computer or in the cloud. It stays linked to the repo, so the agent can push changes back. See Clone, fork or copy.
Working copy
The copy of your repo that the agent edits: a folder on your computer on the VS Code path, or a fresh copy in the cloud on the app path. See The big picture.
Fork
Your own copy of someone else's repo, on GitHub, still linked to the original. A fork of a public repo stays public, and commits in it don't count on your GitHub profile. See Clone, fork or copy.
Branch
A parallel line of work in the same repo. Changes on a branch don't touch the main line until they're merged. See The main branch.
main
The main branch of your repo. GitHub Pages publishes your site from it, so your site changes only when main changes. In the app, Claude works on its own claude/… branch first. See The main branch.
Pull request (PR)
A request to merge the changes on one branch into another. GitHub shows the changes so you can look before you click Merge pull request. See The main branch.
Merge
Combining the changes from one branch into another, such as a claude/… branch into main. See The main branch.
Merge conflict
Two changes touched the same lines, and Git can't tell which to keep. Ask the agent to explain it before you choose. See Commit & push.
Revert
Undoing a commit by adding a new commit that reverses it, so the record stays. See Commit & push.

Your computer

VS Code
A free code editor from Microsoft. On the VS Code path, your agent runs inside it. See VS Code + your agent.
Extension
An add-on that gives VS Code a new feature. The Claude Code and Codex extensions put the agent in a panel inside VS Code. See VS Code + your agent.
Terminal
A window where you type commands instead of clicking. In VS Code, open it with View → Terminal. You'll rarely need it, because the agent runs commands for you.
Trusted folder (Workspace Trust)
VS Code asks whether you trust the authors of the files in a folder. Say no, and it opens the folder in Restricted Mode, with AI agents and the terminal turned off. Trust only folders you made or cloned from someone you trust. See Trusted folders.
GitHub CLI (gh)
A GitHub tool the agent runs on the VS Code path to do GitHub chores for you, such as creating or forking a repo. It can also switch on GitHub Pages, as an optional shortcut. You sign it in once with gh auth login. See Git, Node & GitHub CLI.
Node.js
A free program that runs JavaScript on your computer. Some starters need it for their build step. The agents themselves don't. See Git, Node & GitHub CLI.
Execution policy
The Windows PowerShell setting that decides whether scripts may run. Its starting value blocks the scripts Node's tools use. See Windows: allow scripts.

Publishing

GitHub Pages
GitHub's free website hosting. It publishes one branch and one folder of your repo at https://your-username.github.io/your-repo/. You switch it on yourself, once, in your repo's Settings → Pages, because the agent can't change your repo's settings. See Turn on GitHub Pages.
index.html
The page a site opens with. GitHub Pages needs it named in lowercase, in the folder it publishes from. See Turn on GitHub Pages.
Starter
A working site you copy and have the agent rewrite for your subject. history-of-tampa is one long scrolling story, a way to learn any history subject. startup-india-guide is a multi-page minisite with a sidebar, for any subject that needs several pages, such as a directory or handbook. See Pick a starter.
Build step
A command that turns a site's source files into its finished pages, such as node build.mjs. history-of-tampa has none. startup-india-guide builds its pages into a docs folder. See Pick a starter.
Actions tab
The tab on your repo where GitHub lists its automatic jobs. Each time your site publishes, a run called pages build and deployment appears there, and a green check means it's done. See Turn on GitHub Pages.
