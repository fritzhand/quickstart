• Fork: your own copy of someone else's repo, on GitHub. It stays linked to the original.
  • Fresh copy: a brand-new repo of yours with the starter's files copied in. No link back, and its history starts fresh.
  • Clone: a working copy of a repo, on your computer or in the cloud. It stays linked to the repo it came from, so the agent can push its changes back.

Which one to use

GoodWatch out
ForkFastest: one prompt or one click.A fork of a public repo is always public; you can't make it private. Commits in a fork don't count on your GitHub profile.
Fresh copyHow the real examples were made: history-of-indigo from history-of-tampa, and the Florida ecosystem map from startup-india-guide. You choose public or private, and your commits count on your profile.A few more steps, which the agent does for you.
CloneGives the agent a copy of your repo to edit.On the app path the app clones for you, so you rarely ask for it.

A fork is fine for a first site. Make a fresh copy if you want your work to show on your GitHub profile.

Fork a starter

Fork fritzhand/history-of-tampa into my account and name the fork your-repo.

On the VS Code path, add "Then clone it here and open it." On the app path, start a new session and pick your fork in the repository selector.

Open https://github.com/fritzhand/history-of-tampa and click Fork in the top-right corner. Type your-repo as the repository name, leave the other options as they are, and click Create fork.

Make a fresh copy

  1. Create an empty repo

    Follow Repos: public or private.

  2. Start a session with both repos

    Select your repo and fritzhand/history-of-tampa, as shown in Many repos, one to work in.

  3. Ask for the copy

    Work only in your-username/your-repo. Treat the other repos as read-only reference. Copy every file from fritzhand/history-of-tampa into my repo (not the .git folder), commit and push to main.

Open your projects folder in VS Code, then say:

Create a new public GitHub repository called your-repo and clone it here. Copy every file from https://github.com/fritzhand/history-of-tampa into it (not the .git folder), commit and push to main.

Clone your repo

Nothing to do. Each session clones the repos you pick onto a fresh cloud machine.

Open the folder where you keep projects, then say:

Clone https://github.com/your-username/your-repo into this folder and open it.

Clone your own repo, not the original. The agent can't push to a repo that isn't yours.

Open https://github.com/your-username/your-repo. It shows the starter's files. A fork also says "forked from fritzhand/history-of-tampa" under its name.

If it goes wrong

The agent says it can't push

It's probably working in the original starter, which isn't yours. Tell it which repo to use:

Work only in your-username/your-repo. Treat the other repos as read-only reference.

On the app path, also check that the Claude GitHub App is installed on your repo. See Claude Code in the app.

I forked, but I want my commits to count

Make a fresh copy under a new name, as above, and use that one from now on. You can delete the fork later.

What the agent runs for you 
# Fork, and clone the fork (GitHub CLI)
gh repo fork fritzhand/history-of-tampa --clone --fork-name your-repo

# Fresh copy: both repos side by side, copy everything except .git
rsync -a --exclude .git history-of-tampa/ your-repo/
cd your-repo
git add .
git commit -m "Copy the history-of-tampa starter"
git push origin main

# Clone
git clone https://github.com/your-username/your-repo.git
