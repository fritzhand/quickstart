Before you start, check two things:

  • Your repo is public. On a free GitHub account, Pages works only from public repos.
  • Its name is lowercase. Web addresses are case-sensitive, so a name with capitals is easy to mistype and gets a 404.

Switch it on

Pick the folder that holds your site's index.html: / (root) for history-of-tampa, or /docs for startup-india-guide.

This is a setting on GitHub's website, and the app can't switch it for you. It takes a minute in any browser, including your phone's.

  1. Open https://github.com/your-username/your-repo/settings/pages. Or open your repo, click Settings (inside the More menu if you can't see it), then Pages in the left sidebar.
  2. Under Build and deployment, set Source to Deploy from a branch.
  3. Under Branch, choose main, then the folder: / (root) or /docs.
  4. Click Save.

The agent does it with the GitHub CLI you signed in to in Git, Node & GitHub CLI.

Turn on GitHub Pages for your-username/your-repo from the main branch, root folder (or /docs if the site lives in docs/), using the GitHub CLI, then tell me the URL.
Switch to the App path tab above and follow its four steps. They work in any browser.

Wait for it

The first publish can take up to 10 minutes. To watch it, open your repo's Actions tab: a run called pages build and deployment appears, and a green check means it's done. Settings → Pages then shows "Your site is live at …" with a Visit site button.

Open https://your-username.github.io/your-repo/, typed in lowercase. You see your site, not a 404 page. Bookmark it.
Open the fork's Actions tab. If a banner there asks you to enable workflows, enable them. Then have the agent push any small change, such as "Update PROGRESS.md, then commit and push to main."

If it goes wrong

I get a 404 page
  • Wait the full 10 minutes, then reload.
  • In Settings → Pages, check the branch is main and the folder is the one that holds index.html.
  • The start page must be named index.html, all lowercase.
  • Type the address in lowercase.

Or let the agent look:

My site at https://your-username.github.io/your-repo/ shows a 404. Check that index.html, in lowercase, is in the folder GitHub Pages publishes from on main, tell me which branch and folder Pages should use, and fix anything in the repo.
The page loads, but with no styling or broken images

The page can't find its files, usually because a path starts with /, points to the original owner's site, or doesn't match a file name's capital letters.

Some styles or images don't load on my live site. Make every link to CSS, JavaScript and image files relative, not starting with / and not pointing to another site's address. Check that each file name matches its link exactly, including capital letters. Then commit and push to main.
It still shows the old version

Wait for the green check in the Actions tab. Then open the address in a private or incognito window, which skips the copy your browser saved. Still old? Your change may not be on main; see The main branch.

What the agent runs for you 
# Turn on Pages from main, root folder (use /docs for a site in docs/)
gh api -X POST repos/your-username/your-repo/pages -f "source[branch]=main" -f "source[path]=/"

# Show the Pages settings and the site's address
gh api repos/your-username/your-repo/pages
